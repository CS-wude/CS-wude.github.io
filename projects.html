我通常接哪一段

我主要写 Java 后端，也会把模型、前端和部署串起来。比起从零做一个单页原型，我更常接手那些跨了好几个模块、失败后又很难解释的链路：长任务、流式连接、工具调用、支付回调、模型服务和发布过程。

所以这里不把项目写成“我独立完成了全部”。我会把团队成果和我负责的部分分开，只讲自己实际处理过的问题。

我判断一个功能做没做完，通常不是看它第一次有没有跑通，而是看第二次失败时，我们知不知道该从哪里回来。

反复遇到的问题

现场我会先做什么
长任务堵住接口拆出任务状态，入队执行，先把重试和取消定义清楚。
外部服务不稳定明确超时、熔断和降级，不让一次依赖故障拖垮主流程。
工具调用范围太大先收紧输入、权限和作用域，再谈 Agent 能做多少。
发布只能靠记忆把构建、配置、检查和回滚写进流水线，让下一次发布不靠运气。

我对“做完”的判断

接口通了、页面能点、演示没有报错，这些只能算第一阶段。一个系统真正能交出去，还要能解释自己的状态，能在依赖抖动时保护主链路，也能让另一个人按同样的方式构建和发布。

所以我常把时间花在不太适合截图的地方：事件结构、幂等键、任务检查点、日志上下文、健康检查和回滚入口。它们很少出现在功能列表里，却决定了项目三个月后还好不好改。
