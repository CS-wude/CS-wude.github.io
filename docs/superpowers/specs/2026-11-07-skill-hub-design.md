# 博客 Skill Hub 设计

## 用户确认的目标

为 GitHub 博客增加独立公开的 Skill Hub 页面，通过菜单或首页入口访问。每个技能包含描述及来源 URL，可链接原作者，也可链接自己的技能仓库。列表随博客前端代码更新，不使用 Issues、运行时 API 或单独的管理后台。另建一个公开仓库收录技能。

## 实现选择

沿用博客原生 HTML/CSS/ES Modules 与 GitHub Pages。采用 skills.html + data/skills.js 的静态目录，比直接在 HTML 逐项维护更便于增删、分类和校验；动态后台超出本次需要。此项是基于用户已选定“写入前端、随前端更新”的具体实现建议。

## 页面与交互

- 主导航新增 Skill Hub，首页增加可见入口，内容目录接入同一页面。
- 页面沿用暖白、墨色、黄色点缀及现有导航，不引入另一套主题。
- 顶部说明收录目的、来源区分及自己的仓库入口。
- 卡片包含名称、中文用途描述、分类、作者/来源与“查看来源”链接。自己的内容标识为“WUDE 维护”，外部内容明确作者，不冒充原创。
- 支持关键词搜索、分类筛选、来源筛选、结果数量及空结果提示；URL 保存筛选条件以便分享与返回。
- 主要卡片在构建期输出 HTML；浏览器只做筛选，无 JavaScript 仍可打开来源。
- 首批只收录核验过的公开来源；不展示虚构下载量、评分或未经验证的安装命令。

## 新仓库（待用户确认的命名）

建议创建公开仓库 CS-wude/skillhub。初始包括 README、收录规范、技能目录说明及可填写的模板。外部技能保留链接与署名，原创目录只加入用户明确决定公开的技能。不得直接复制电脑中的私有 Skills、项目环境、凭据或第三方付费素材。

博客技能目录仍以 data/skills.js 为唯一公开数据源；仓库说明链接回博客。初期不做双向自动同步。仓库创建后再填入真实的仓库链接。

## 验证与交付

检查数据唯一性、有效 HTTPS 来源、搜索/筛选组合、URL 恢复、转义与内部导航；运行现有测试和静态构建；浏览器检查桌面、手机、空状态和键盘操作。交付本地预览。创建公开仓库属于用户此次明确要求；博客提交/部署在收到本次发布指令后执行。

## 需要确认

按上述范围实施，公开仓库使用 CS-wude/skillhub。若用户不提供首批名单，由实现者选择少量已核验的公开技能入口，后续从数据文件维护。
