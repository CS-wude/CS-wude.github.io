这个目录怎么用

首页负责让人快速看到作品，内容页负责把项目讲清楚。每个项目可以拥有一个独立页面，左侧目录承担站点级导航，右侧目录只导航当前文章。

先写真实内容，再做视觉包装。一个项目只需要回答清楚背景、目标、过程、结果四件事。

项目如何组织

1. 项目概览

用两三句话说明项目服务谁、解决什么问题，以及你在其中承担的职责。概览应该让不了解上下文的人也能快速进入状态。

2. 过程与判断

展示关键路径，不必记录每一步。更值得写的是：有哪些约束、为什么选择这个方案、放弃过哪些方向。

3. 结果与后续

结果可以是上线产品、开源仓库、数据变化，也可以是一次明确的失败和复盘。真实比完整更有价值。

内容分类

分类适合放什么状态
产品项目完整产品、网站、应用与长期维护的工具持续增加
开放实验创意编码、原型、技术验证和短期探索持续增加
随笔记录设计判断、开发笔记和项目复盘按需更新

发布到 GitHub Pages

这些页面都是普通 HTML、CSS 和 JavaScript 文件，不依赖服务器。推送到 GitHub 仓库后，在 Pages 设置中选择 main 分支和根目录即可发布。

  1. 把站点文件放入仓库根目录。
  2. 在仓库设置中打开 Pages。
  3. 选择从分支部署，并保存。
  4. 后续推送代码会自动更新网站。
